# SDCodex

Stitch project `projects/4032984165089508769` (SDCodex). Dark-first workstation for model/checkpoint/LoRA management.

## Working boundaries
- All work stays inside this checkout. The **test environment — including its Docker container and image — must remain untouched**: never modify it, stop it, rebuild/replace it, or retag the image it runs. It may be read/inspected for troubleshooting only. This keeps the updater and app testable in isolation from the dev files and stack.
- Concrete rule: never run bare `docker compose up/build` here (it claims `container_name: sdcodex` and retags `sdcodex:latest`, which the test deployment uses). Dev stacks go through `docker-compose.dev.yml` (project/container `sdcodex-dev`, image `sdcodex:dev`).

## Stack
- `app/` — Vite 8 + React 19 + TS + Tailwind 3 (slice 1: Library). Run commands from `app/`.
- Build: `npm run build` (`tsc -b && vite build`) · Dev: `npm run dev` · Lint: `npm run lint` (`oxlint`) · Preview: `npm run preview`
- No test runner yet.
- Sidebar navigation icons live in `app/src/components/fanIcon.tsx`; render them as inline SVG rather than icon-font ligatures, which can fall back to visible icon-name text when the font fails to load. The sidebar brand mark is `app/public/sdcodex.svg`.
- Sidebar is a 64px icon rail that widens to 240px on hover (labels clipped/faded, content overlaid like `OldCode/sidebar-menu-hover-show-hide-css`); the pin shown at its top-right while expanded keeps it open and reserves layout width (`localStorage` `sdcodex.sidebar-pinned.v1`). Selected rows shrink to the 48px rail tile (closed right border) when collapsed. There is no topbar collapse button.
- Model-card grids are in Explorer, Home, and Library. When changing column counts, check all three responsive grids and validate the target viewport against Tailwind's breakpoints. If the running UI differs from the built source, confirm which app version/deployment the browser is serving before assuming the CSS change failed.
- Core views in `app/src/views/` (`Explorer` = live Civitai API, `Library` = local mocks, `Core` = Home + Queue stub). API client `app/src/lib/civitai.ts`, queue store `app/src/lib/queue.ts` (localStorage until backend lands).
- `Detail` view = per-model versions/files + creator→search link (mirrors OldCode `/model/<id>`). Queue items carry `modelId`/`versionId` per `DownloadManager.add_task`. Library `Scanner` uses File System Access API + `fetchVersionByHash` (mirrors `scanner.scan_directory`); Chromium-only, mocks work everywhere. Global `/` focuses search.
- Floating `ModelModal` (zoom-out open) replaces the old detail page: tags, version pills, wheel-cycled gallery + checkerboard lightbox, Details table (author/type/base/hash/updated), per-file hashes with Download/Delete, description, embedded PNG generation data (Auto1111 parameters / Comfy prompt+workflow) with a ComfyCaption-plugin note. Explorer + Library cards open it.
- Scan engine lives in `app/src/lib/scan.ts` and runs from Settings → Model dirs (per-row Link + Scan, global Scan all); folder picks persist in IndexedDB (`lib/idb.ts`), records mirror `Download` rows (`lib/library.ts`). Library page shows results only.
- Library shows one section per configured category only (Embedding/VAE/etc. appear once you add their folder); entries come from server `/api/library` rows plus local scan records. Categories accept multiple paths (`dir_<Type>`, `dir_<Type>__N`); server and browser scans both recurse into subfolders. Folder categories ≠ Civitai types — `lib/categories.ts` maps API types (TextualInversion→Embedding, …) for grouping; scans record the folder category. Browser scan records carry their real folder key/path per file, and the base-model chip backfills from the `<name>.metadata.json` sidecar, the safetensors header, then folder/filename tokens (`baseModelFromPath`) — server rows do the same header read in `GET /api/library`. The chip is tinted with the model type accent (category color, else `TYPE_HUE`).
- `Settings` view (tabs: Download dirs, API key, Users & SSO, System) mirrors OldCode `/settings` tabs. Dir keys (`dir_<type>`, custom) and API key persist to localStorage under the same names the backend `Setting` table will adopt; Civitai client sends Bearer token when set. Auth/SSO + self-update panels are honest read-only stubs until the backend lands.
- Auth is frontend-local preview shaped like the backend (`lib/auth.ts` mirrors `User`/`OidcConfig`): blocking gate (no session = no app), bootstrap creates the first user as admin with a PBKDF2-SHA256 password hash (browser stand-in for OldCode scrypt; min 8 chars), avatar shows initials, fan offers Sign in/out. When the backend is reachable it owns auth truth: startup adopts the server user/session, fresh origins get server login instead of re-bootstrap, and gate submits hit `/api/auth/*` directly. Profile edits push to `PUT /api/profile` (display/email/avatar) and startup pulls the full row, so refresh/logout never show stale data. OIDC manager (admin-only, same page) stores provider rows locally with real discovery-Test and PKCE sign-in URLs; no passwords stored client-side. Sidebar has no Settings entry — gear in the radial fan routes there.

## Backend
- `backend/` — Flask + SQLAlchemy (SQLite `backend/data/sdcodex.db`, gitignored). Revived from `OldCode/` as package `sdcodex`; serves JSON at `/api` (`api_v1.py`: health, auth, settings, downloads, library, scan, OIDC). Run: `python3 run.py` from `backend/` (port 5000).
- Frontend talks same-origin `/api` (Vite proxy in dev, backend serves in prod) via `app/src/lib/backend.ts`. Backend-first with localStorage fallback: startup pulls settings, saves push through, auth bootstrap/login mirrors the User row + cookie, queue POSTs to the real `DownloadManager` worker.
- Start everything with `./start.sh` (venv + backend :5000, then Vite :5173; Ctrl+C stops both; `--backend-only` / `--frontend-only` / `--no-install` flags).
- Civitai calls go through the dev `/civitai` proxy (preflight rejects browser Bearer headers cross-origin).
- Plugin background work stays visible app-wide: a plugin declares `task_status` (`{label, path, page}`) in its manifest, its route returns `{active, state, current, total, detail, message, started_at}`, and the core aggregates every installed plugin at `GET /api/plugin-tasks` (`backend/sdcodex/assistant.py::plugin_tasks`). `PluginTaskFloat` polls it every 2 s and offers an "Open <plugin>" jump. AI Renamer reattaches to a running job from `/ai-renamer/api/jobs/active`; ComfyCaption restores its batch on load.
- Assistant + agent tools share one registry (`backend/sdcodex/assistant.py`): `list_plugins`, `search_models` (server-side Civitai, returns a `search` action the Explorer applies), and `run_plugin_task`, plus one tool per plugin-declared `assistant_actions` entry. `POST /api/assistant/chat` runs an OpenAI-compatible tool loop (4 rounds max) and returns `{reply, actions, pending, toolsUsed}`; destructive actions come back as `pending` until the UI re-sends them in `approved`. `backend/sdcodex/mcp.py` exposes the same registry as MCP (JSON-RPC over POST at `/api/mcp`, bearer token, `initialize`/`tools/list`/`tools/call`); agents have no session cookie, so tool calls mint a short-lived admin session and delete it afterwards.
- Assistant endpoint/model/key and the MCP toggle + token live in the `Setting` table (`assistant_base_url`, `assistant_model`, `assistant_api_key`, `mcp_enabled`, `mcp_token`) behind `/api/assistant/*` and `/api/mcp/settings` (admin-only writes). When configured, the global topbar search box becomes the assistant chat bar (`app/src/components/assistantBar.tsx`).

## Plugin pages and publishing
- Plugin pages are static HTML under `plugins/<PluginName>/pages/`, embedded by the core as an iframe at `/api/plugins/<plugin-id>/page/<page-slug>`. Keep each manifest `nav_items[].page` aligned with its HTML filename and let the core sidebar provide page navigation.
- Links between plugin pages must use the full route `/api/plugins/<plugin-id>/page/<page-slug>`; relative links to `.html` files do not resolve through the page endpoint.
- Plugin folders are independent Git repositories. For a published plugin update, bump `plugin.json`, commit and push the plugin repo, then update the matching version in `Plugin-Hub/plugins.json` and commit/push the Plugin Hub repo. The Docker test environment at `/home/naked/games/SDCodex` is read-only and must not be modified.
- Shared disk picker: plugin pages reuse the Gallery plugin's browser instead of rolling their own. Embed `/api/plugins/gallery/page/picker?mode=folder&root=<abs>` in an iframe and listen for `{type:'sdcodex:pick', path, relative, file}` (or `sdcodex:pick-cancel`); it lists folders plus live image thumbnails via `/gallery/api/picker/list` and `/gallery/api/picker/file`. AI Renamer and ComfyCaption open it from "Change Folder" / "Browse".
- Plugin Hub → Updates: one **Update** click pulls core and every installed git-backed plugin, then rebuilds/restarts. The progress dialog shows an "Updating plugins" phase and logs each plugin's pull; dirty or unreachable plugins are skipped without aborting the rest.
- Plugins expose agent actions declaratively: `assistant_actions: [{name, description, method, path, params: [{name, type, required, description}], confirm}]`. The core turns each entry into a tool (`plugin__<id>__<action>`) for both the assistant and MCP; `{param}` placeholders fill from path, other params go to the query string (GET) or JSON body (POST), and `confirm: true` marks it destructive (assistant asks first, MCP runs it directly).
- GalleryDL task page: `plugins/GalleryDL/pages/tasks.html`, route slug `tasks`; task APIs are under `/gdl/api`, with per-task history and recent downloads at `/gdl/api/tasks/<slug>/history` and `/recent`.

## Post-task commit & push
- After every task, if any changes were made: increment `VERSION`, update `Plugin-Hub/plugins.json` core/plugin versions, and update the `plugin.json` versions of any changed plugins. Then commit and push all core (`git add -A; git commit -m "..."; git push upstream HEAD`), pluginhub (`Plugin-Hub: git commit --allow-empty -m "..."; git push origin HEAD`), and all plugin repos (`plugins/*/` push `HEAD`).
